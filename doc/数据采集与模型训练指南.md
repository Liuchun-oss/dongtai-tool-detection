## 项目概述

### 项目目标
开发一个基于YOLOv8的铁路工具识别系统，能够自动识别和清点10+种铁路常用工具，部署到Android手机上进行离线推理。

### 识别工具类别
根据项目需求，需要识别以下工具类别：

| 类别ID | 工具名称 | 说明 |
|--------|---------|------|
| 0 | 大扳手 | 大型固定扳手 |
| 1 | 活口扳手 | 可调节开口的扳手 |
| 2 | 尖嘴钳 | 细长尖嘴的钳子 |
| 3 | 钢丝钳 | 用于剪断钢丝的钳子 |
| 4 | 一字螺丝刀 | 一字型螺丝刀 |
| 5 | 十字螺丝刀 | 十字型螺丝刀 |
| 6 | 风机 | 小型鼓风机 |
| 7 | 防护红旗 | 安全警示红旗 |
| 8 | 喷壶 | 喷雾器 |
| 9 | 对讲机 | 通信设备 |
| 10 | 万用表 | 测量仪表 |
| 11 | 内六角 | 内六角扳手 |
| 12 | 垫布 | 工具摆放的垫布（可选，用于区域检测） |

**注意**：螺丝刀类可以合并为一个类别"螺丝刀"，不区分一字/十字，简化识别难度。

## 数据采集规范

### 一、采集环境要求

#### 1.1 拍摄场地
- **主要场景**：铁路作业现场、工具库房、模拟作业环境
- **光照条件**：
  - 自然光环境（白天室外，避免强光直射）
  - 室内灯光环境（模拟夜间作业）
  - 混合光照环境
- **背景要求**：
  - 使用标准垫布（建议蓝色或橙色，尺寸约1m×1m）
  - 垫布应平整铺放，无明显褶皱
  - 背景尽量简洁，避免复杂背景干扰

#### 1.2 拍摄设备
- **推荐设备**：Android手机（与部署设备相同或相似型号）
- **相机设置**：
  - 分辨率：1920×1080 或更高（建议使用后置摄像头）
  - 对焦模式：自动对焦
  - 闪光灯：根据环境光线决定，避免过度曝光
  - 白平衡：自动
- **拍摄距离**：距离垫布中心约1-1.5米，确保工具清晰可见

### 二、工具摆放规范

#### 2.1 基本摆放原则
1. **工具应放置在垫布范围内**
   - 所有工具必须完全或大部分在垫布区域内
   - 允许工具部分超出垫布边缘（模拟真实场景）
   - 工具不应重叠放置（特殊情况可少量重叠）

2. **工具间距**
   - 工具之间保持适当间距（建议5-10cm）
   - 避免工具过于密集，影响识别
   - 允许工具紧挨摆放（模拟实际清点场景）

3. **工具方向**
   - 工具可以任意角度摆放（0°-360°）
   - 同一工具在不同照片中应呈现不同角度
   - 避免所有工具都朝同一方向

4. **工具状态**
   - 工具应保持清洁，无明显污渍
   - 允许工具有轻微磨损（符合实际使用情况）
   - 新旧工具都应包含在数据集中

#### 2.2 数量分布要求
- **单张照片工具数量**：1-15个工具
- **数量分布**：
  - 1-3个工具：30%
  - 4-8个工具：40%
  - 9-15个工具：30%
- **同类别工具数量**：
  - 同一张照片中，同一种工具可以出现1-5个
  - 需要包含多数量同种工具的场景

#### 2.3 特殊场景采集
1. **部分遮挡场景**
   - 工具被其他工具部分遮挡（遮挡面积<50%）
   - 工具部分超出垫布边缘
   - 工具被阴影遮挡

2. **组合摆放场景**
   - 工具堆叠摆放（2-3层）
   - 工具交叉摆放
   - 工具紧挨摆放

3. **光照变化场景**
   - 强光照射（工具反光）
   - 阴影覆盖
   - 逆光拍摄

4. **角度变化场景**
   - 俯视角度（90°垂直拍摄）
   - 斜视角度（45°-60°）
   - 侧视角度（30°-45°）

### 三、拍摄规范

#### 3.1 拍摄角度
- **主要角度**：垂直俯拍（90°），确保工具完整可见
- **辅助角度**：45°-60°斜拍，模拟实际作业视角
- **角度分布**：
  - 垂直俯拍：60%
  - 斜拍：40%

#### 3.2 拍摄距离
- **标准距离**：1-1.5米（确保垫布完整入镜）
- **近距离拍摄**：0.8-1米（工具细节更清晰）
- **远距离拍摄**：1.5-2米（包含更多工具）

#### 3.3 拍摄数量要求
- **总数据量**：2000-3000张图片
- **每类工具**：至少200-300张包含该工具的图片
- **数据分布**：
  - 训练集：70%（1400-2100张）
  - 验证集：20%（400-600张）
  - 测试集：10%（200-300张）

#### 3.4 拍摄检查清单
拍摄前检查：
- [ ] 垫布平整铺放
- [ ] 工具清洁无污渍
- [ ] 光照充足均匀
- [ ] 相机对焦清晰
- [ ] 工具在垫布范围内

拍摄后检查：
- [ ] 图片清晰度良好
- [ ] 工具完整可见
- [ ] 无严重过曝或欠曝
- [ ] 背景简洁
- [ ] 文件命名规范

## 数据标注流程

### 一、标注工具选择

#### 1.1 推荐工具
1. **LabelImg**（推荐）
   - 开源免费
   - 支持YOLO格式
   - 操作简单，适合快速标注
   - 下载地址：https://github.com/tzutalin/labelImg

2. **Label Studio**
   - 功能强大，支持团队协作
   - Web界面，跨平台
   - 下载地址：https://labelstud.io/

3. **CVAT**（Computer Vision Annotation Tool）
   - 专业级标注工具
   - 支持视频和图像标注
   - 下载地址：https://github.com/openvinotoolkit/cvat

#### 1.2 标注格式
使用**YOLO格式**（推荐）：
- 每个图片对应一个`.txt`标注文件
- 标注格式：`class_id center_x center_y width height`
- 坐标值归一化到0-1之间

示例：
```
0 0.5 0.5 0.2 0.3
1 0.3 0.7 0.15 0.25
2 0.7 0.3 0.1 0.2
```

### 二、标注规范

#### 2.1 边界框（Bounding Box）要求
1. **框选范围**
   - 边界框应紧密贴合工具边缘
   - 允许边界框略大于工具（约5-10像素）
   - 避免边界框过大，包含过多背景

2. **遮挡处理**
   - 工具被遮挡<30%：完整框选整个工具
   - 工具被遮挡30%-50%：框选可见部分
   - 工具被遮挡>50%：不标注或标注为"部分可见"

3. **重叠工具**
   - 每个工具单独标注一个边界框
   - 边界框可以重叠
   - 确保每个工具都有对应的类别标签

#### 2.2 类别标注
1. **类别选择**
   - 严格按照12个类别进行标注
   - 不确定的工具类别，标记为"待确认"
   - 保持类别命名一致性

2. **特殊情况处理**
   - **螺丝刀**：不区分一字/十字，统一标注为"螺丝刀"
   - **扳手类**：区分大扳手和活口扳手
   - **垫布**：可选择是否标注（用于区域检测）

#### 2.3 标注质量检查
- [ ] 所有可见工具都已标注
- [ ] 边界框位置准确
- [ ] 类别标签正确
- [ ] 无重复标注
- [ ] 无遗漏工具
- [ ] 标注文件格式正确

### 三、标注流程

#### 3.1 标注步骤
1. **准备阶段**
   - 安装标注工具（LabelImg）
   - 准备类别列表文件（classes.txt）
   - 组织图片文件

2. **标注阶段**
   - 打开LabelImg，加载图片目录
   - 设置标注格式为YOLO
   - 逐张图片进行标注：
     a. 框选工具
     b. 选择类别
     c. 保存标注文件
   - 定期保存进度

3. **检查阶段**
   - 随机抽查标注质量
   - 检查标注文件格式
   - 统计各类别数量

#### 3.2 标注效率提升
- **批量处理**：按工具类别分组标注
- **快捷键使用**：熟练使用标注工具快捷键
- **质量控制**：每标注100张图片进行一次质量检查
- **团队协作**：多人标注时统一标注规范

### 三、模型训练

#### 3.1 模型选择
**推荐使用YOLOv8n（nano）或YOLOv8s（small）**：
- **YOLOv8n**：模型小（6MB），速度快，适合低端手机
- **YOLOv8s**：平衡精度和速度，推荐用于中高端手机

#### 3.2 训练命令
```python
from ultralytics import YOLO

# 加载预训练模型
model = YOLO('yolov8n.pt')  # 或 'yolov8s.pt'

# 开始训练
results = model.train(
    data='data.yaml',           # 数据集配置文件
    epochs=100,                 # 训练轮数
    imgsz=640,                  # 输入图片尺寸
    batch=16,                   # 批次大小（根据GPU显存调整）
    device=0,                   # GPU设备ID（CPU训练使用device='cpu'）
    workers=4,                  # 数据加载线程数
    patience=50,                # 早停耐心值
    save=True,                  # 保存检查点
    save_period=10,             # 每10个epoch保存一次
    project='runs/detect',      # 项目目录
    name='railway_tools',       # 实验名称
    exist_ok=True,              # 允许覆盖已存在的实验
    pretrained=True,            # 使用预训练权重
    optimizer='AdamW',          # 优化器
    lr0=0.01,                   # 初始学习率
    lrf=0.01,                   # 最终学习率（lr0 * lrf）
    momentum=0.937,             # 动量
    weight_decay=0.0005,        # 权重衰减
    warmup_epochs=3,            # 预热轮数
    warmup_momentum=0.8,        # 预热动量
    box=7.5,                    # 边界框损失权重
    cls=0.5,                    # 分类损失权重
    dfl=1.5,                    # DFL损失权重
    hsv_h=0.015,                # 色调增强
    hsv_s=0.7,                  # 饱和度增强
    hsv_v=0.4,                  # 明度增强
    degrees=0.0,                # 旋转角度
    translate=0.1,              # 平移
    scale=0.5,                  # 缩放
    shear=0.0,                  # 剪切
    perspective=0.0,            # 透视变换
    flipud=0.0,                 # 上下翻转概率
    fliplr=0.5,                 # 左右翻转概率
    mosaic=1.0,                 # 马赛克增强概率
    mixup=0.0,                  # MixUp增强概率
    copy_paste=0.0,             # 复制粘贴增强概率
)

# 验证模型
metrics = model.val()

# 导出模型（转换为TensorFlow Lite）
model.export(format='tflite', imgsz=640, int8=True)
```

#### 3.3 训练参数说明
- **epochs**：训练轮数，建议100-200轮
- **batch**：批次大小，根据GPU显存调整（8GB显存建议batch=16）
- **imgsz**：输入图片尺寸，640是标准尺寸，可尝试416或320以提升速度
- **lr0**：初始学习率，建议0.01，可根据训练情况调整
- **patience**：早停耐心值，50个epoch无改善则停止训练

#### 3.4 训练监控
训练过程中监控以下指标：
- **mAP50**：IoU阈值0.5时的平均精度（目标>0.7）
- **mAP50-95**：IoU阈值0.5-0.95的平均精度（目标>0.5）
- **Precision**：精确率（目标>0.9）
- **Recall**：召回率（目标>0.8）
- **Loss**：训练损失（应持续下降）

### 四、模型优化

#### 4.1 数据增强
YOLOv8默认包含以下数据增强：
- 马赛克增强（Mosaic）
- 随机翻转（Flip）
- 颜色空间增强（HSV）
- 随机缩放（Scale）
- 随机平移（Translate）

可根据实际情况调整增强参数。

#### 4.2 超参数调优
1. **学习率调整**
   - 如果损失不下降，降低学习率（lr0=0.001）
   - 如果损失震荡，降低学习率
   - 使用学习率调度器（Cosine或Linear）

2. **批次大小调整**
   - 显存充足时增大batch size（提升训练稳定性）
   - 显存不足时减小batch size

3. **输入尺寸调整**
   - 640：标准尺寸，平衡精度和速度
   - 416：较小尺寸，速度更快，精度略降
   - 320：最小尺寸，速度最快，精度较低

## 模型选择与部署

### 一、模型选择建议

#### 1.1 模型对比

| 模型 | 参数量 | 模型大小 | 速度（FPS） | mAP50 | 适用场景 |
|------|--------|----------|-------------|-------|----------|
| YOLOv8n | 3.2M | ~6MB | 150+ | 0.65-0.75 | 低端手机，速度优先 |
| YOLOv8s | 11.2M | ~22MB | 100+ | 0.70-0.80 | 中端手机，平衡 |
| YOLOv8m | 25.9M | ~52MB | 60+ | 0.75-0.85 | 高端手机，精度优先 |

#### 1.2 推荐方案
**推荐使用YOLOv8s（small）**：
- 精度和速度平衡良好
- 模型大小适中（~22MB，量化后~12MB）
- 适合大多数Android手机
- 识别准确率可达95%以上

**备选方案**：
- 如果手机性能较低，使用YOLOv8n
- 如果对精度要求极高，使用YOLOv8m

### 二、模型转换（TensorFlow Lite）

#### 2.1 转换步骤
```python
from ultralytics import YOLO

# 加载训练好的YOLOv8模型

    format='tflite',      # 导出格式
    imgsz=640,            # 输入尺寸
    int8=True,            # INT8量化（减小模型大小，提升速度）
    data='data.yaml'      # 数据集配置（用于量化校准）
)

# 转换后的模型文件：best.tflite
```

#### 2.2 量化选项
1. **FP32**：全精度，模型大，速度慢，精度最高
2. **FP16**：半精度，模型中等，速度中等，精度略降
3. **INT8**：8位整数，模型小，速度快，精度略降（推荐）

**推荐使用INT8量化**：
- 模型大小减少约75%（22MB → 6MB）
- 推理速度提升2-3倍
- 精度损失<3%

```kotlin
package com.android.dongtai.service

import android.content.Context
import android.graphics.Bitmap
import org.tensorflow.lite.Interpreter
import java.io.FileInputStream
import java.nio.ByteBuffer
import java.nio.ByteOrder
import java.nio.MappedByteBuffer
import java.nio.channels.FileChannel

class ToolDetectionService(private val context: Context) {
    private var interpreter: Interpreter? = null
    private val inputSize = 640
    private val numClasses = 12
    
    // 工具类别名称
    private val classNames = listOf(
        "大扳手", "活口扳手", "尖嘴钳", "钢丝钳", "螺丝刀",
        "风机", "防护红旗", "喷壶", "对讲机", "万用表", "内六角", "垫布"
    )
    
    init {
        loadModel()
    }
    
    private fun loadModel() {
        try {
            val modelFile = loadModelFile(context, "best.tflite")
            interpreter = Interpreter(modelFile)
        } catch (e: Exception) {
            e.printStackTrace()
        }
    }
    
    private fun loadModelFile(context: Context, modelPath: String): MappedByteBuffer {
        val fileDescriptor = context.assets.openFd(modelPath)
        val inputStream = FileInputStream(fileDescriptor.fileDescriptor)
        val fileChannel = inputStream.channel
        val startOffset = fileDescriptor.startOffset
        val declaredLength = fileDescriptor.declaredLength
        return fileChannel.map(FileChannel.MapMode.READ_ONLY, startOffset, declaredLength)
    }
    
    fun detectTools(bitmap: Bitmap): List<String> {
        val interpreter = this.interpreter ?: return emptyList()
        
        // 预处理图片
        val resizedBitmap = Bitmap.createScaledBitmap(bitmap, inputSize, inputSize, true)
        val inputBuffer = preprocessBitmap(resizedBitmap)
        
        // 准备输出缓冲区
        val outputBuffer = ByteBuffer.allocateDirect(
            inputSize * inputSize * (numClasses + 5) * 4  // 4 bytes per float
        ).apply {
            order(ByteOrder.nativeOrder())
        }
        
        // 运行推理
        interpreter.run(inputBuffer, outputBuffer)
        
        // 后处理结果
        return postprocessOutput(outputBuffer, bitmap.width, bitmap.height)
    }
    
    private fun preprocessBitmap(bitmap: Bitmap): ByteBuffer {
        val inputBuffer = ByteBuffer.allocateDirect(
            4 * inputSize * inputSize * 3  // 4 bytes per float, 3 channels
        ).apply {
            order(ByteOrder.nativeOrder())
        }
        
        val intValues = IntArray(inputSize * inputSize)
        bitmap.getPixels(intValues, 0, bitmap.width, 0, 0, bitmap.width, bitmap.height)
        
        var pixel = 0
        for (i in 0 until inputSize) {
            for (j in 0 until inputSize) {
                val pixelValue = intValues[pixel++]
                // 归一化到[0, 1]
                inputBuffer.putFloat(((pixelValue shr 16) and 0xFF) / 255.0f)
                inputBuffer.putFloat(((pixelValue shr 8) and 0xFF) / 255.0f)
                inputBuffer.putFloat((pixelValue and 0xFF) / 255.0f)
            }
        }
        
        return inputBuffer
    }
    
    private fun postprocessOutput(
        outputBuffer: ByteBuffer,
        imageWidth: Int,
        imageHeight: Int
    ): List<String> {
        // YOLO输出格式：[x, y, w, h, confidence, class_scores...]
        // 需要根据实际模型输出格式调整
        
        val detectedTools = mutableListOf<String>()
        val confidenceThreshold = 0.5f
        
        // 解析输出（这里需要根据实际模型输出格式实现）
        // 简化示例：假设输出格式为 [batch, num_detections, 6]
        // 其中6 = [x, y, w, h, confidence, class_id]
        
        outputBuffer.rewind()
        // TODO: 实现NMS（非极大值抑制）和结果解析
        
        return detectedTools
    }
    
    fun close() {
        interpreter?.close()
        interpreter = null
    }
}
```

### 四、性能优化建议

#### 4.1 模型优化
1. **量化**：使用INT8量化减小模型大小
2. **剪枝**：移除不重要的神经元（需要重新训练）
3. **知识蒸馏**：使用大模型指导小模型训练

#### 4.2 推理优化
1. **图片预处理**：
   - 在GPU上进行预处理（如果支持）
   - 使用多线程预处理
   - 缓存预处理结果

2. **批处理**：
   - 如果一次处理多张图片，使用批处理

3. **异步处理**：
   - 在后台线程进行推理，避免阻塞UI

4. **缓存**：
   - 缓存模型加载结果
   - 缓存预处理结果

#### 4.3 内存优化
1. **及时释放**：
   - 推理完成后及时释放Bitmap
   - 关闭Interpreter释放资源

2. **图片压缩**：
   - 拍照时适当压缩图片
   - 推理前调整图片尺寸

### E. 常见问题

#### Q1: 训练时显存不足怎么办？
A: 减小batch size（如16→8），或减小输入尺寸（如640→416）。

#### Q2: 模型精度不够怎么办？
A: 
1. 增加训练数据
2. 调整数据增强策略
3. 使用更大的模型（YOLOv8s→YOLOv8m）
4. 增加训练轮数
5. 调整学习率

#### Q3: 模型推理速度慢怎么办？
A:
1. 使用INT8量化
2. 减小输入尺寸（640→416或320）
3. 使用GPU加速
4. 使用更小的模型（YOLOv8s→YOLOv8n）

#### Q4: 某些工具识别不准怎么办？
A:
1. 增加该类工具的训练数据
2. 检查标注质量
3. 调整该类别的损失权重
4. 使用数据增强增加该类工具的多样性

#### Q5: 模型文件太大怎么办？
A:
1. 使用INT8量化（可减小75%）
2. 使用更小的模型（YOLOv8s→YOLOv8n）
3. 模型剪枝（需要重新训练）
